Drop a guard here once and every consumer gets it on the next pin bump.
A plugin is an ES module: `export const name = 'id'; export async function run({cwd, baselineDir}) { return { fails: [string] } }`.
Baseline violations in the consumer under `.company-guards/<name>-baseline.json`; fail only on new or worse.

- `schedule-registration` (shadow): a new schedule (GitHub cron, wrangler cron, vercel.json cron, systemd timer, launchd interval) must register into the platform's shared scheduler and say why no event can do the job (inline `scheduler: <id> why-not-event: <...>`, `.company-guards/schedules.json`, or a `clock` block in canon/automation-registry.jsonl). Baseline: `.company-guards/schedule-registration-baseline.json` (array of site keys; only shrinks). Generate it from `run().current`.
- `lockfile-majors` (shadow, JOV-13093): declare new major keys (including 0.x minors) in PR bodies with `Dependency-Upgrade: <name> <base-version> -> <head-version>`; declare new importer dependencies with `Dependency-Add: <name>`. Bullets/backticks are allowed; stale declarations and near-name additions fail qualification. New loose specifiers, stale/missing locks and releases under three days old fail; `security-advisory` exempts age only. Migration gates warn with their probe. Runs on PR events or defined `PR_BODY`, using `SIZE_BASE_SHA` or the merge commit's first parent; push, merge queue, local and unrelated diffs skip (no network for skips); missing bases warn. Remains shadow until unit 2 auto-declarations and consumer self-testing are wired.
- `auto-update` (shadow): the company auto-update policy (`canon/update-policy.json`, `policy/UPDATE-POLICY.md`). Each repo has a Dependabot or Renovate config covering every shipped ecosystem and composite-action directory, cooldowns on npm/pip, third-party actions pinned to full SHAs, a Dependabot auto-merge lane, holds with a date or Linear key (dated holds expire after 60 days), Node on the Active LTS major and a fresh wrangler `compatibility_date`. Tracked files only, no network.

`node scripts/consumer-selftest.mjs [--repos a,b] [--allow-unreachable]` compares each consumer's pinned and candidate enforcing findings without running drift. Unreachable clones fail closed unless explicitly allowed; invalid pins or incomplete guard runs always remain unverified and fail closed.
